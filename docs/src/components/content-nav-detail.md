# TrContentNav 详细说明

本文档用于补充 [TrContentNav 内容导航组件](./content-nav)，重点说明每个 prop、slot 的适用场景、设计目的和使用边界。

## 组件定位

`TrContentNav` 是一个用于长内容区域的目录导航组件。它的核心目标不是渲染一组普通列表，而是解决以下问题：

- 在长内容区域中，为用户提供稳定的当前位置感知
- 在目录项与正文锚点之间建立明确映射
- 在低干扰的默认状态下保留可发现性
- 在需要时提供搜索、跳转、键盘访问和轻量反馈

它适合以下场景：

- 文章、文档、知识库章节目录
- 聊天场景中的 turn 导航
- 与 `TrBubble`、`TrBubbleList` 组合的对话内容回跳
- 任何存在“滚动正文 + 目录索引”关系的页面

它不适合以下场景：

- 普通页面侧边菜单
- 路由导航菜单
- 完全独立于滚动内容的快捷操作列表

`TrContentNav` 的设计前提是“目录项必须能映射到真实内容锚点”，所以它与 `registry`、`scrollContainer` 的配合是第一优先级。

## 设计理念

### 1. 受控优先

`TrContentNav` 支持非受控使用，但更推荐受控方式接入：

- `v-model:active-id`
- `v-model:expanded`
- `v-model:query`

这样做的原因是：

- 内容导航通常属于页面级状态，而不是孤立组件状态
- 外部受控更方便和业务埋点、布局模式、阅读状态联动
- 文档页、工作台、聊天页面往往都需要在组件外决定何时展开、何时搜索、何时同步当前项

### 2. 锚点注册优先于 DOM 扫描

组件通过 `registry` 接收 `id -> HTMLElement` 的映射，而不是在内部扫描 DOM。

这样设计的原因是：

- 避免依赖 DOM 层级和选择器偶然性
- 更适合虚拟列表、异步渲染、动态插拔内容
- 让“目录数据”和“正文锚点”之间的关系更明确

### 3. 固定目录点与悬浮面板分离

组件默认的视觉交付形态是：

- 折叠态仅保留目录点
- 展开态从目录点锚位拉出悬浮面板
- `placement="right"` 时向左展开
- `placement="left"` 时向右展开

这样设计的目标是：

- 减少长正文阅读时的视觉干扰
- 保证展开前后目录点位置稳定
- 让“目录点”和“面板”形成明确的交互层次

### 4. 搜索是可选增强，不是默认前提

搜索通过 `search` 配置显式启用，而不是默认常开。

原因是：

- 短内容场景并不需要搜索
- 搜索区会改变面板层级和信息密度
- 把搜索做成可选能力，有利于组件在不同复杂度场景中复用

## Props 详解

## 数据与上下文

### `items`

- 类型：`ContentNavItem[]`
- 默认值：无

这是组件的目录项数据源。每一项至少需要：

- `id`：目录项唯一标识
- `label`：目录项显示文本

常见使用场景：

- 文档章节标题列表
- 消息 turn 摘要列表
- 知识块、问答块、卡片块的导航索引

设计理念：

- `items` 只描述“目录结构”，不直接描述 DOM
- 组件不会根据 `items` 自动查找目标节点，锚点关系由 `registry` 单独提供

建议：

- `id` 与锚点注册时使用的 `id` 保持完全一致
- `label` 保持简短，超长文本应优先通过 `tooltipText` 补充

### `registry`

- 类型：`ContentNavRegistry`
- 默认值：内部 registry

用于注册目录项对应的目标元素，是组件建立“目录 -> 正文”映射的关键输入。

常见使用场景：

- 在 `v-for` 渲染章节时，将 `section.id` 与 DOM 元素注册到同一个 registry
- 在聊天内容中，将 turn id 与对应 bubble 或段落容器注册起来

设计理念：

- 把“数据映射”和“DOM 注册”显式化
- 避免在组件内部依赖选择器扫描
- 为复杂场景保留扩展空间

建议：

- 目录项与目标锚点共用一套 `id`
- 锚点元素尽量选“滚动到这里即可”的稳定节点，而不是嵌套过深的局部元素

### `scrollContainer`

- 类型：`HTMLElement | null`
- 默认值：无

指定当前内容区的滚动容器。组件通过它感知滚动位置，并在点击目录项后执行滚动跳转。

常见使用场景：

- 文档主内容区有独立滚动容器
- 聊天消息区使用内部滚动，而不是整页滚动
- 工作台布局里，中间面板单独滚动

设计理念：

- 目录导航应服务于“内容区”的阅读，而不是默认依赖整页滚动
- 明确滚动容器后，active 计算和跳转行为更稳定

如果页面已经通过 `provideContentNavScrollContainer()` 提供了滚动容器，也可以不再单独传 `scrollContainer`。

## 受控状态

### `activeId`

- 类型：`string`
- 默认值：非受控

表示当前高亮的目录项。

常见使用场景：

- 由组件根据滚动位置自动更新，再通过 `v-model:active-id` 同步给外部
- 外部业务希望在切换内容时主动指定当前项

设计理念：

- 当前项既是 UI 状态，也是页面阅读状态
- 保持受控能力，方便与外部页面状态同步

建议：

- 如果页面需要记录阅读进度或联动其他区域，优先使用受控模式

### `expanded`

- 类型：`boolean`
- 默认值：非受控

表示面板是否处于展开状态。

常见使用场景：

- 需要显式演示“目录点 -> 悬浮面板”的展开过程
- 页面在某些模式下希望常驻展开
- 页面希望在 hover 之外，通过外部交互控制面板开关

设计理念：

- 展开态既可以由 hover/focus 驱动，也可以由业务外部驱动
- 将其做成受控状态，可以避免组件行为与页面意图冲突

建议：

- 文档、演示、引导场景中，推荐直接受控 `expanded`
- 如果只是普通内容导航，可让组件自行管理展开态

### `query`

- 类型：`string`
- 默认值：非受控

表示当前搜索词。

常见使用场景：

- 外部保留搜索词状态
- 需要在面板外部同步显示当前搜索词
- 需要在清空内容、切换 tab、切换会话时统一重置搜索

设计理念：

- 搜索词属于显式用户输入，外部受控更利于和页面状态联动

## 展示与交互

### `placement`

- 类型：`'left' | 'right'`
- 默认值：`'right'`

控制目录停靠位置。

视觉规则：

- `right`：目录点固定在右侧，面板向左展开
- `left`：目录点固定在左侧，面板向右展开

常见使用场景：

- 聊天区习惯在右侧提供目录导航
- 内容区左侧已有主导航，只能将内容目录放到右侧
- 某些文档布局希望目录贴近正文左边缘

设计理念：

- `placement` 改变的是“锚点与面板方向关系”，不是简单的水平对齐
- 展开前后目录点应保持稳定，不因方向切换而漂移

### `collapsible`

- 类型：`boolean`
- 默认值：`true`

控制组件是否允许收起。

常见使用场景：

- 普通阅读页：保留折叠态，减少干扰
- 常驻目录场景：设为 `false`，直接固定展开

设计理念：

- 折叠态适合长正文场景
- 非折叠态适合管理后台、工作台等需要持续可见目录的场景

### `search`

- 类型：`false | ContentNavSearchOptions`
- 默认值：`false`

控制是否启用内置搜索区，以及搜索的行为配置。

常见使用场景：

- 内容较长，目录项数量多于 5 到 8 条时，启用搜索会更实用
- 面板空间有限，但仍希望快速定位目录项

设计理念：

- 搜索是目录导航的增强能力，不应默认侵入所有场景
- 使用对象配置而不是多个散 props，有利于集中管理搜索相关行为

### `minItems`

- 类型：`number`
- 默认值：`2`

小于该数量时不渲染组件。

常见使用场景：

- 只有 1 个目录项时，没有独立展示内容导航的必要

设计理念：

- 避免为极短内容强行渲染无意义导航

### `mobileBehavior`

- 类型：`'hidden' | 'inline' | 'drawer' | 'sheet'`
- 默认值：`'hidden'`

控制组件在移动端或窄宽度场景中的展示方式。

常见使用场景：

- 文档页 demo：可用 `inline` 避免在窄容器里直接消失
- 实际产品页：移动端可能选择 `drawer` 或 `sheet`

设计理念：

- 悬浮目录点在窄宽度下不一定总是成立
- 将移动端策略做成可配置能力，方便不同业务按需接入

### `showTooltipOnTruncate`

- 类型：`boolean`
- 默认值：`true`

控制目录项在文本截断时是否显示 tooltip。

常见使用场景：

- 目录文本较长，但展开面板宽度需要受控
- 需要在不增加面板宽度的前提下保留完整文本可读性

设计理念：

- tooltip 只在截断时出现，避免信息噪音

### `keyboardMode`

- 类型：`'none' | 'basic' | 'roving'`
- 默认值：`'basic'`

控制目录的键盘交互方式。

常见使用场景：

- 默认业务场景使用 `basic`
- 需要更强键盘可访问性时使用 `roving`

设计理念：

- 把键盘复杂度做成可选层级，而不是强迫所有场景承担同样交互成本

### `ariaLabel`

- 类型：`string`
- 默认值：`'Content navigation'`

提供导航区域的可访问名称。

常见使用场景：

- 会话目录导航
- 章节目录导航
- 工作台内容索引导航

建议：

- 使用明确业务语义，例如“会话目录导航”“正文目录导航”

### `emptyText`

- 类型：`string`
- 默认值：`'No matching items'`

用于搜索无结果时的空状态文案。

设计理念：

- 搜索空结果是正常场景，应当有清晰反馈

### `floating`

- 类型：`boolean`
- 默认值：`true`

控制是否使用悬浮面板模式。

常见使用场景：

- 普通内容阅读场景：保持 `true`
- 某些嵌入布局或内部面板场景：可设为 `false`

设计理念：

- 对外暴露这个能力，是为了让组件既能服务阅读区，也能服务局部面板

## 行为与滚动

### `resolveActive`

- 类型：`ContentNavActiveResolver`
- 默认值：默认 resolver

用于自定义当前项计算规则。

常见使用场景：

- 聊天 turn 导航更适合“顶部阈值”策略
- 文章 TOC 更适合“最近可见标题”策略

设计理念：

- 不把“当前项”算法写死在组件内部
- 允许业务根据内容结构决定 active 判定方式

### `jumpOffset`

- 类型：`number | (() => number)`
- 默认值：`0`

用于控制跳转时的顶部偏移。

常见使用场景：

- 页面有固定 header
- 内容区顶部有吸顶工具栏

设计理念：

- 点击目录跳转时，应以可读区域为目标，而不是机械地让锚点贴到容器顶端

### `smoothScroll`

- 类型：`boolean`
- 默认值：`true`

控制是否使用平滑滚动。

常见使用场景：

- 阅读型页面通常保持 `true`
- 某些测试场景或低动效场景可以关闭

### `jumpFeedback`

- 类型：`ContentNavJumpFeedbackController | false`
- 默认值：`createContentNavFlashFeedback()`

控制目录跳转后的目标反馈。

常见使用场景：

- 需要帮助用户确认“我跳到了哪里”
- 聊天内容较长，跳转后用户容易丢失目标位置

设计理念：

- 跳转反馈应是轻量提示，而不是常驻高亮
- 视觉表现由控制器定义，组件只负责生命周期

## Slots 详解

### `item`

- 参数：`{ item, segments, active, expanded, highlighted }`

用于自定义目录项主体内容。

适用场景：

- 目录项需要展示副标题、时间、标签、序号
- 目录项需要根据 `segments` 自定义高亮渲染
- 业务希望统一目录项文案结构

设计理念：

- 允许业务自定义“项内容”，但不破坏目录点、对齐和滚动逻辑

建议：

- 保持目录项高度和交互区域稳定
- 避免在 `item` slot 中加入过多复杂操作

### `marker`

- 参数：`{ item, active }`

用于自定义目录点。

适用场景：

- 用数字、图标、缩略标记替代默认圆点
- 根据业务状态切换不同 marker 形态

设计理念：

- marker 是目录点视觉锚位，不应依赖 item 内容宽度变化

建议：

- 自定义 marker 时尽量维持尺寸稳定
- 不要让 marker 在展开前后占位发生变化

### `search`

- 参数：`{ query, setQuery, options }`

用于自定义搜索区。

适用场景：

- 需要替换默认搜索框样式
- 需要在搜索区加入图标、说明、快捷操作

设计理念：

- 搜索的状态管理仍由组件提供
- 搜索区域的具体 UI 允许业务替换

建议：

- 自定义搜索区时，仍建议把输入行为交回 `setQuery`

### `empty`

- 参数：无

用于自定义空结果区域。

适用场景：

- 搜索无结果时展示更符合业务语气的提示
- 需要加入“清空搜索词”“返回全部目录”等引导

设计理念：

- 空状态是交互流程的一部分，不只是占位文案

## 常见组合方式

### 与 TrBubble / TrBubbleList 组合

适合聊天内容、问答流、长会话摘要导航。

推荐做法：

- 用消息摘要或用户问题生成 `items`
- 用 `registry` 注册每段消息的锚点节点
- 在聊天消息滚动区上提供 `scrollContainer`

### 与文章章节组合

适合文档页、知识库、帮助中心。

推荐做法：

- 直接使用章节标题作为 `label`
- 将每个章节容器注册为锚点
- 根据页面是否有固定顶栏设置 `jumpOffset`

### 与工作台面板组合

适合右侧概览、报告目录、信息块索引。

推荐做法：

- 目录项信息保持简短
- 根据布局决定 `floating` 或 `inline`

## 使用建议

- 当目录项较少时，可保持 `search=false`
- 当页面希望展示完整交互链路时，建议受控 `expanded`
- 当正文有固定头部遮挡时，优先设置 `jumpOffset`
- 当目录与正文映射关系复杂时，优先把数据映射逻辑放在业务层处理
