## 1. 目标、范围与不变量

### 1.1 本次目标

让图片以“左侧缩略图、右侧文件名”的胶囊形式参与普通文本流，支持文本编辑、图片插入与移动、图文选区、删除、复制粘贴、撤销重做，以及可恢复的结构化文档。

独立性有两个可验证的标准：

1. 不依赖 Sender 的编辑器 fixture 能运行全部编排核心功能。
2. 不启用扩展时，Sender 的原有数据模型、事件参数和编辑行为保持兼容。

### 1.2 范围

包含：文本、段落、原子行内图片；本地资源和可选异步处理适配器；有序导出；Sender 最小接入；基本键盘和非拖动指针操作。

不包含：GUI 或聊天应用集成、服务端上传实现、模型请求格式、图片编辑与缩放、自由画布、图注、富文本格式工具栏、协同编辑、刷新后恢复本地二进制文件、跨应用图片引用共享。

Mention / Template / Suggestion 与新扩展的组合不作为第一版承诺。必须验证它们在未启用新扩展时不回归；不能宣称任意扩展可以安全混用。

### 1.3 必须始终成立的不变量

| 编号 | 不变量 | 观察方式 |
| --- | --- | --- |
| I1 | 文档是顺序的唯一来源 | 对比文档 JSON、可视顺序和导出 parts |
| I2 | 一个草稿内每个图片出现位置具有唯一 nodeId | 遍历节点检查唯一性 |
| I3 | 移动保留身份，复制生成新身份 | 比较操作前后 nodeId / resourceId |
| I4 | 一个用户编排动作可以整体撤销 | 操作后一次 undo 恢复操作前文档 |
| I5 | 异步状态变化不改变文档，不增加编辑历史 | 比较文档与 undo/redo 行为 |
| I6 | 已删除、已丢弃草稿不会被迟到结果重新插入内容 | 可控异步任务复现 |
| I7 | 资源不可解析时仍保留图片位置和名称 | 恢复缺资源的快照 |
| I8 | 空文档不能因为注册了对象而被判定为可提交 | 检查 registry 和按钮状态 |
| I9 | 旧快照不随之后的编辑和资源进度变化 | 导出后修改草稿，再比较旧快照 |
| I10 | 不启用扩展时不接管既有 Sender 行为 | 原有回归用例 |

核心先放入 `packages/components/src/sender/extensions/image-composition/`，沿用现有扩展组织方式。目录位置不代表运行时依赖 Sender。

Vue 组件采用 Composition API、`<script setup lang="ts">`。实现前读取 Vue 技能的 reactivity、sfc、component-data-flow、composables 核心参考，按 frontend-change-checklist 检查契约、主题和可访问性。

### 2.2 生命周期所有权

- 草稿会话持有资源 store；控制器订阅编辑器事务，维护只读派生状态。
- NodeView 只订阅它引用的资源，卸载时取消订阅，不释放整个资源。
- Sender 插槽里的桥接组件仅建立、解除注册；布局切换导致桥接组件重挂载时，不销毁草稿和控制器。
- 草稿 owner 显式 dispose 时取消任务、释放本会话创建的 blob URL、取消所有监听。
- 调用方提供的 URL 不归本模块所有，不能调用 revokeObjectURL。
- 同一控制器禁止同时绑定两个编辑器；第一版不做共享编辑会话。

## 3. 实现前固定的数据与交互契约

### 3.1 文档、资源与快照

图片节点：`inline: true`、`group: 'inline'`、`atom: true`、`selectable: true`、`draggable: true`。属性限定为 `nodeId`、`resourceId`、`name`。节点没有可编辑子内容。

资源保存：稳定 `resourceId`、原始文件（可选）、受控预览地址、状态、进度、错误、远端描述（可选）、任务代次。文件名只作为显示数据，不能作为资源身份。

文档快照以 `{ version: 1, doc: ... }` 包装受支持的 Tiptap JSON。资源描述另行导出；不能声称只保存 doc 就能恢复本地文件。恢复时可由调用方提供资源解析器，找不到的资源显示 unavailable。

有序 parts 仅包含 text 和 image。段落之间输出一个 `\n`，相邻空段落保留相应换行；不对内容 trim；空文档的标准空段落导出空 parts；相邻文本片段可以合并，但不能跨越图片改变顺序。

纯文本投影用 `[图片：文件名]` 表示图片。该表示只用于降级和可读展示，不用于从字符串恢复图片。字数统计只统计真实文本，图片名称和降级标记不计入；图片数量单独派生。

快照导入先校验、后替换，失败时原文档不变。未知版本、未知节点、重复 nodeId、缺少必需属性返回结构化错误；不依赖 Tiptap 自动丢弃不认识的节点。第一版完整恢复通过新草稿/新编辑器初始化完成，避免旧历史跨草稿恢复资源；编辑中的 clear 属于可撤销操作。

### 3.2 控制器最小能力

拟定能力而非要求逐项创建公开 API：

- 创建/绑定编辑器与 dispose；获取只读派生状态并订阅变化。
- 捕获插入书签、插入本地文件或已知资源、取消待插入请求。
- 按 nodeId 删除或移动；移动目标必须是合法文档位置。
- 导出文档、parts、文本；按校验过的快照初始化新草稿。
- 清空当前文档（可撤销）；结束会话由 owner 明确处理。

所有修改命令返回成功或明确原因，例如 disabled、invalid-position、unsupported-file、composition-pending；不静默部分修改。批量文件校验可以部分接受，但返回 accepted/rejected 列表，合格文件统一事务插入。

控制器不提供第二个可写文档副本。第一版不新增 Sender 富文档 v-model，也不把字符串 v-model 与控制器同时作为可写来源。Sender 的 input 文本可供观察；`setContent(string)` 仍表示整体替换，富文档接入方应使用控制器。

### 3.3 编辑与历史

| 操作 | 固定行为 |
| --- | --- |
| 插入 | 替换当前选区；同批图片按传入顺序插入，插入后光标位于最后一张后 |
| 文件选择 | 打开前保存 SelectionBookmark，随事务映射；取消无变化；同会话书签失效回退末尾；草稿已换代则丢弃请求 |
| 胶囊点击 | 选中节点；不默认打开预览 |
| Backspace / Delete | 非空图文选区直接删除；节点已选中则删除；紧邻节点的空选区先选择、再删除；两个方向均验证 |
| 普通输入 | 段首、段尾、相邻图片间可输入；不向用户文本注入占位空格或零宽字符 |
| 移动 | 保留 nodeId/resourceId；不使用切成文本块的 sortable；原地移动是 no-op |
| 复制粘贴 | 新出现位置使用新 nodeId；同会话可共享资源 |
| 剪切粘贴 | 剪切删除一次；粘贴作为新插入并生成新 nodeId，避免撤销源删除后身份冲突 |
| 内部原生拖动 | 按 move 处理、保留身份；修饰键复制按 copy 处理 |
| undo / redo | 一批插入、一次移动、一次删除各是一项操作；资源进度不进入历史 |
| 输入法 | composing 期间不执行节点重排和文档替换；插入请求排队，结束后映射位置再执行 |
| clear | 清空文档，可撤销；保留草稿资源以支持恢复 |
| disabled | 阻止用户修改及控制器编辑命令；异步资源完成可更新显示；解除后恢复编辑 |

图文混合选区使用原生选择和剪贴板；第一版保证其删除、复制和剪切。混合选区的原生拖动单独验证，不为此引入第二套选区系统。

### 3.4 样式和替代操作

- 胶囊整体不可折行；宽度不超过容器，名称省略，完整名称可访问。使用当前字体和主题变量，不固定整行高度。
- 缩略图尺寸预留，加载/失败不改变胶囊高度；禁用原生 img 拖动。
- 状态不能只靠颜色；删除/重试按钮有可访问名称，点击不触发拖动。
- 方向键可跨过/选中节点，Tab 可到达操作，Escape 退出操作并恢复编辑位置。
- 提供“移动到…”操作：选中节点后进入落点选择，单击目标确认、Escape 取消；键盘可移动目标光标并确认。移动状态下的 Enter 必须优先完成移动，不能触发 Sender 提交；若现有宿主优先级阻挡，阶段 2/7 需记录并增加局部协调。
- 首版优先验证桌面 Chromium。触屏使用非拖动移动入口；不把桌面原生拖动通过当成触屏拖动支持。

### 3.5 资源、校验与并发

- 本地可用、处理中、可用、失败、不可用是资源状态；是否可提交由接入方决定，编排层不硬编码上传完成门槛。
- 支持格式在第一版显式列举，建议 PNG/JPEG/WebP/GIF；SVG 和无法解码的输入明确拒绝。MIME/扩展名只是初筛，需确认可解码；GIF 保留原文件，不把缩略图当成提交资源。
- 文件大小、图片总数由配置约束；总数按当前文档图片出现次数计数，复制/粘贴/拖入也执行限制。资源去重不改变数量口径。
- 选择后校验并插入节点，再调用可选处理适配器。适配器约定可取消信号、进度回调、成功/失败；不实现真实上传端点。
- 同资源的多个引用共享状态，删除一个不能取消仍被其他引用使用的任务。
- 最后一个引用删除后可以取消当前任务，但保留本地文件到草稿结束；撤销恢复时自动恢复为本地可用状态，有处理适配器则重新发起任务。
- 每次启动/重试都有 generation；回调同时检查草稿会话、资源身份、generation、disposed 状态。取消不可依赖底层任务一定响应 AbortSignal。
- URL、File、错误对象等运行时引用不能直接泄漏进可序列化快照；对外状态也不能暴露可变内部 store。

## 4. Sender 最小改动策略

### 4.1 已有能力，优先复用

- `extensions` 安装节点。
- 暴露的 editor / `useSenderContext` 接入控制器。
- `useSenderContentRegistration` 注册派生的图文 payload；`extra.externalPayloads` 传出有序快照。
- 原有 `defaultActions.submit.disabled` 可由接入方结合资源状态控制；不把上传策略写进核心。

新扩展接入期间，有实质内容才注册 payload；空文档或仅空白返回 null。图片即使资源失败，也仍是文档内容。非空文本文档也可输出 rich parts，但这是启用适配层后的行为；不启用时事件参数个数保持原样。

订阅 document-changing 事务更新文档投影；资源订阅只更新状态和资源描述。registry 提供值必须是新建的不可变快照，不能把 store 或 editor.state 直接交给提交事件。注册注销后重新挂载必须立即读取当前文档，不依赖未来再输入一次。

### 4.2 已知接缝与拟定补丁

| 位置 | 当前事实 | 最小方向与验证要求 |
| --- | --- | --- |
| `sender/composables/useEditor.ts` | 顶层 handlePaste 优先取 text/plain | 新增可选的窄粘贴处理入口（暂名 pasteHandler），true 表示消费，false 回落原逻辑；未配置时行为不变；不整体开放 editorOptions |
| `sender/composables/useSenderCore.ts` | hasEditorContent 只识别模板/文本 | 接收可选的行内内容存在信号（暂名 hasInlineContent），与旧判定 OR；只表示编辑器内节点，不混入外部附件；纯图片清空按钮可用 |
| `sender/index.type.ts` | 没有上述入口 | 仅增加验证确有必要的可选属性，不修改原有 v-model 和 submit 参数类型 |
| `sender/composables/useModeSwitch.ts` | setMode 后 focus('end') | 保留并映射选区；原先没有焦点时不抢焦点；局部修复并覆盖旧换行和切换用例 |
| `sender/composables/useSenderCore.ts` 的键盘优先级 | Sender 先处理提交快捷键 | 验证移动模式/节点操作键是否被拦截；优先在操作控件或明确消费的 DOM 事件层处理，只有证据证明必要才增加可选键盘处理入口 |
| 扩展导出与包根入口 | 现有公开入口由导出链决定 | 最后阶段明确新 API 名称和公开路径，避免仅凭源目录承诺可导入路径 |

上述两个可选属性是阶段 2 的首选试验方案，不是已冻结公共 API。若现有正式扩展机制可干净表达同一契约，应减少新增属性；禁止通过运行时反复覆盖 Sender 的 editorProps、读取 DOM 或伪造文本规避接缝。

disabled 先由适配层将宿主 disabled 与编辑器 editable 同步，并保护命令和按钮；loading 不自动等同 disabled。验证 Sender 原有 setOptions 操作不会覆盖扩展或适配状态。

首版不修改 attachments、upload-button、drag-overlay 的内部实现，也不修改 chat、kit。用 File[] 和局部 drop 入口完成集成。若叠加外层 DragOverlay 会拦截内部移动，记录为未支持的组合，不能静默宣称兼容。

**小步验证**

**用例**：`ImageCompositionEditing.spec.ts`。

**阶段结论**：原子行内节点是否满足基本编辑；哪些边界确实需要自定义插件。原生行为已正确的地方不再增加插件。

**实现**：最薄的 adapter 与 Sender fixture；用当前文档派生 payload；临时使用固定资源。分别验证粘贴、存在性和布局焦点，补丁一个一个增加。

**小步验证**

1. 空文档不注册有效内容；纯图片可提交；纯文本及图文都能按文档顺序导出。
2. 清除最后图片后提交状态立即更新；clearable=true 时纯图片有清空入口。
3. 反复单/多行切换只保留一份注册，资源不销毁，光标不跳末尾。
4. 没有适配层的 Sender 原有 submit 参数个数不变，外部附件行为不变。
5. 最小粘贴 handler 消费一次；返回 false 时恢复原有单/多行纯文本粘贴。
6. 用模拟移动模式检查 Enter、Escape、Tab 的事件优先级，为 P3 确认可行接缝。
7. 禁用后输入、胶囊删除、拖入与控制器修改均无效；解除禁用可继续。

**用例**：`SenderImageComposition.spec.ts`，并定向运行旧 `SenderModelSync.spec.ts` 与基础 E2E。

**阶段结论**：列出实际需要修改的 Sender 文件、每一处理由和默认行为；在这里冻结必要接缝，不能等所有功能完成后才发现要重写 Sender。

**停止条件**：需要同时维护两个文档状态、反复 monkey-patch editorProps、或接入必须修改大量既有扩展。重新收敛接入方案。

### P3：完成拖动和可替代的移动交互

**实现**：复用原生内部拖动，补充落点和外部文件分流；统一 move 命令；实现单击选择落点与键盘确认；图片按钮不触发拖动。

**小步验证**

1. 同段向前/向后移动；拖入两个字符之间；跨段和跨空段移动。
2. 目标在原选区内时 no-op；落到编辑器外或 Escape 取消时不改文档。
3. 移动保持 ID 和图片数量，复制拖动产生新 ID；所有变更正确计算删除源节点后的目标位置。
4. 拖动过程中容器滚动、落点可见；相邻图片间落点明确。
5. 非拖动指针操作和键盘操作产生与拖动相同的文档；操作中的 Enter 不触发提交。
6. 一次移动一次 undo/redo；节点完整，不出现重复或残留 DOM。

**用例**：`ImageCompositionDrag.spec.ts`。命令级移动和浏览器拖动分开测试，不能只调用 move 命令证明拖动可用。

**阶段结论**：文字和图片的位置可可靠重排；记录真实指针验证范围及未覆盖设备。

### P4：建立数据导出与恢复闭环

**实现**：serialization、校验、只读快照、parts/text 投影、控制器查询 API。

**固定样例**：空文档、纯图片、`A[图1] B`、相邻图片、多段空行、中文/emoji、同资源多引用、缺资源。

**小步验证**

1. 对每个样例检查 `doc -> snapshot -> 新编辑器` 的语义相等，包括空白、段落与节点 ID。
2. parts 顺序与文档严格一致；文本换行有明确预期，不能沿用会吞掉段落的旧提取工具。
3. 图文顺序改变、图片增减也发出文档变化，不能只比较 getText()。
4. 导出后继续编辑或更新资源，旧快照不变。
5. 非法版本/节点/重复 ID 导入失败且不修改旧草稿；缺资源保留占位和文件名。
6. 新草稿初始化不继承旧草稿历史或异步回调。

**用例**：`ImageCompositionSerialization.spec.ts`，可在现有 CT 框架内测试纯函数和编辑器往返，不为此增加测试框架。

**阶段结论**：编排结果可以完整表达与恢复；明确 doc 快照不能独自持久化本地 File。

### P5：打通剪贴板与统一文件入口

**实现**：复制/剪切序列化、粘贴分类、文件验证、统一批量插入、文件选择书签。内部引用带会话标记且需在资源 store 中解析；不信任任意外部 data 属性。

**小步验证**

1. 文本、图片、混合选区、跨段落选区分别复制粘贴；新 nodeId 唯一，资源引用可用。
2. 剪切粘贴后逐次 undo/redo，无身份冲突或重复内容。
3. 截图 File、外部多文件拖入、同一事件的 File+HTML 只插入一份。
4. 普通网页富 HTML 默认按纯文本降级，不引入未经支持的格式或远程图片。
5. 外部/过期会话图片标记降级为可读文本，不能伪造资源引用。
6. 格式、大小、总图片数量对选择、粘贴、复制、拖入一致生效；部分失败返回清单。
7. 文件选择期间编辑原文，最终插入映射后的位置；取消无操作；换草稿后迟到选择结果无效。
8. 实际操作系统剪贴板复制到纯文本目标，看到明确图片文字占位。

**用例**：`ImageCompositionClipboard.spec.ts`。合成 ClipboardEvent 用于分支测试，另保留真实剪贴板人工验收。

**阶段结论**：所有入口得到一致文档，不重复、不静默丢资源；清楚区分同会话与跨应用能力。

### P6：完成资源生命周期和异步竞态

**实现**：resource-store、可控处理适配器、取消与 generation 校验、局部资源订阅。使用手动 resolve/reject 的 fake adapter，不依赖真实上传服务或网络时延。

**小步验证**

1. 多文件逆序完成，文档顺序仍为选择顺序；进度更新前后文档 JSON 不变。
2. 上传中移动，完成后仍在新位置；删除后完成不会出现节点。
3. 失败后重试，旧任务晚完成不能覆盖新结果。
4. 同资源复制两次，删除一个不取消另一个；最后引用删除后取消；撤销恢复可重新处理。
5. clear 后迟到结果不复活节点；undo clear 正确恢复。
6. 丢弃草稿/卸载后迟到回调不写入新草稿、不产生异常。
7. 记录 create/revokeObjectURL 与订阅数：节点卸载不提前 revoke，会话 dispose 后全部自有 URL 释放且无监听残留。
8. 状态渲染不污染 undo；恢复不可用资源时保留胶囊并提供明确状态。

**用例**：`ImageCompositionResources.spec.ts`。

**阶段结论**：资源进度和失败不干扰编排；所有权和结束会话的释放可证明。

### P7：完成集成回归、真实交互和布局验证

**实现**：仅修复前面暴露的局部问题；不新增业务流程。不自动修改 Suggestion/Template 以扩大组合支持。

**必需验证**

- Sender 原有 CT：ModelSync、Suggestion、Header；原有 Sender E2E：基础、Mention、Template、Suggestion。
- 新适配层：纯图片提交、空状态、clear/undo、禁用、loading、字数边界、图片数量限制、注册重挂载。
- 单行溢出转多行后在原光标继续输入；手动切换时焦点/选区不丢；布局切换不产生历史记录。
- Windows 真实中文输入法：图片两侧及相邻图片间输入；组合时打开选择、确认/取消输入、触发布局切换；确认回车不能误提交。
- 320/480/800px 容器、normal/small、亮暗主题、200% 缩放、长文件名、图片加载失败、达到 maxRows 后滚动可见。
- 键盘操作、非拖动指针移动、操作按钮的名称和焦点恢复；屏幕阅读器至少检查名称、状态、按钮语义。
- 真实文件拖入和真实内部拖动；合成 DataTransfer 通过不代替这两项。

**阶段结论**：分别列出自动化通过、人工通过、未验证环境。Chromium 自动化通过不能写成 Firefox/WebKit/移动端兼容。若要宣称更广支持，增加相应浏览器测试与真实设备验证后再扩大结论。

**停止条件**：基础输入丢字符、图文丢失/重复、撤销不可靠、纯图片无法清空、未启用扩展的 Sender 行为回归。上述问题不能以“已知限制”交付。

### P8：审核公开接口、示例和最终变更

**实现**

1. 导出经过验证的最小类型、扩展和控制器/适配器入口；暂不同时增加多套等价静态方法。
2. 补充一个最小图文编排示例和一个模拟资源状态示例，放在 `docs/demos/sender/`。
3. 在 `docs/src/components/sender.md` 补充接入、状态所有权、字符串模型边界、导出、限制；按组件文档规范审计涉及的公开契约。
4. 更新源文件、类型和公共入口，做包根导入/声明检查；不把源目录路径写成不存在的 package exports。
5. 审查最终 diff，每一处 Sender 修改都对应一个失败用例和修复后的证据。

**通过标准**：两个示例可运行、公共 API 可从实际入口导入、必要测试通过、无无关文件改动，最终记录能直接说明做了什么和未覆盖什么。

## 6. 用例组织与诊断方式

拟新增测试集中在 `packages/test/component/sender/`，文件名前缀为 `ImageComposition` 或 `SenderImageComposition`。独立 fixture 和 Sender fixture 分开，共用小型测试数据与 fake resource adapter，不用一个巨大 fixture 同时承担所有情况。

测试观察面只暴露只读快照和明确操作；用户路径尽量通过键盘、鼠标、文件选择等触发。用于诊断的直接命令不能替代交互断言。

推荐固定数据：两个不同小 PNG、同名不同文件、长中文文件名、GIF、损坏图片、非图片、超过限制的文件。大文件可构造测试字节，不提交庞大二进制素材。

| 类别 | 自动化重点 | 仍需实际交互 |
| --- | --- | --- |
| 文档语义 | 顺序、ID、往返、空白、校验 | 无额外要求 |
| 历史 | 插入/删除/移动和资源更新隔离 | 真实快捷键与混合输入 |
| 拖动 | move 与 copy、目标映射、取消 | 实际鼠标拖动、文件管理器拖入、滚动边缘 |
| 剪贴板 | 事件分类、内部标记、重复处理 | 操作系统剪贴板、截图粘贴 |
| IME | 合成 composition 分支与延后执行 | Windows 真实中文输入法 |
| 资源 | 可控任务、迟到回调、取消、释放计数 | 缩略图渲染和失败提示 |
| 可访问性 | 名称、焦点、按键和禁止误提交 | 非拖动操作与屏幕阅读器基本检查 |

失败先保存操作序列、文档/选区快照和 trace，再缩小到独立 fixture。禁止用增加 sleep、跳过断言或仅重跑到通过来结束失败。涉及时序的用例优先用可控 Promise 和可观察状态等待。

## 7. 运行命令与前置条件

以下为未来进入实现后的命令，不表示本轮执行过。工作目录均为仓库根目录。准备阶段确认 package scripts 没有变化后使用。

```powershell
# 首次准备；只在进入实现和运行验证后执行
pnpm install --frozen-lockfile
pnpm -F tiny-robot-test exec playwright install chromium

# 现有公开入口测试依赖构建产物；首次准备采用仓库既有依赖构建入口
pnpm build:components

# 静态检查
pnpm -F @opentiny/tiny-robot type-check
pnpm -F tiny-robot-test type-check:ct

# 新功能的快速 CT：仅选择新功能文件
pnpm -F tiny-robot-test exec playwright test -c playwright-ct.config.ts ImageComposition --project=chromium

# 原有与新增 Sender CT
pnpm -F tiny-robot-test exec playwright test -c playwright-ct.config.ts component/sender --project=chromium

# Sender E2E；配置会启动 localhost:3333 的测试应用
pnpm -F tiny-robot-test exec playwright test -c playwright.config.ts src/sender/specs --project=chromium
```

更小的阶段检查在上述 CT 命令中使用对应文件名；文件名来自阶段计划，创建前不能运行。不要用根 `pnpm test` 或全仓库 `pnpm lint` 作为每步快速检查：前者包含无关测试，后者当前带 `--fix`。

快速迭代：优先让新增 fixture 显式导入功能源码，避免每次重新构建整个仓库；如果 fixture 直接导入 Tiptap 包，需要按 pnpm 严格依赖规则补充测试包直接 devDependency，并保持 3.17.1 版本。不得依赖偶然的 node_modules 提升。

现有 Sender 回归通过包根读取 dist。每次修改生产组件后、运行这类回归前，必须刷新相关组件产物；依赖已准备时可使用 `pnpm -F @opentiny/tiny-robot exec vite build` 做组件 ES 产物更新，不需要每步构建所有无关包。最终公开入口验证再运行组件标准 build，包含原有产物流程。

即使新增 fixture 读取源码，CT 公共入口仍会加载 dist/style.css；若改了 Sender 全局样式，需要同步产物或明确在新 fixture 引入实际源样式，不能让旧 CSS 蒙混通过。采用哪种方式在 P0 记录，保持一致。

端口 3100/3333 已被占用时先确认所属进程和 worktree。不要复用来源不明的现有服务器；不要结束用户无关进程。测试配置默认可复用服务器，这不证明服务器来自当前分支。

## 8. 依赖顺序与可交付里程碑

依赖顺序：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8`。

| 里程碑 | 包含阶段 | 可直接体验/核对的结果 |
| --- | --- | --- |
| M1：基本可行 | P0–P2 | 独立节点可编辑，Sender 接缝及改动清单已验证 |
| M2：编排闭环 | P3–P4 | 能移动、撤销、导出和恢复，文档顺序正确 |
| M3：真实输入闭环 | P5–P6 | 文件/剪贴板入口一致，异步资源不破坏文档 |
| M4：可交付 | P7–P8 | 原有行为回归、实际交互证据、公共 API 和示例完整 |

每个里程碑都可以停下来审查已完成结果，但不是必须向用户请求继续许可。P1 原型能显示胶囊不等于 M4 完成。

## 9. 风险与决策点

| 风险 | 提前暴露阶段 | 决策规则 |
| --- | --- | --- |
| 原子节点边界无法正常输入 | P1 | 优先检查 schema/NodeView；不先填充隐藏字符 |
| Sender 阻挡粘贴或移动确认键 | P2 | 加窄的可选接缝并验证默认行为，不整体开放编辑器所有配置 |
| 纯图片清空与原判空混淆 | P2 | 仅补行内内容信号，不把外部附件改成编辑器内容 |
| 模式切换造成光标丢失 | P2 | 保留选区和焦点所有权，并回归原换行语义 |
| 原生拖动和 ID 规范化冲突 | P3 | 依据 move/copy 语义处理；禁止每次 docChanged 都重建 ID |
| 字符串模型抹掉图片 | P2/P4 | 明确结构化控制器为唯一写入口，不增加双主状态 |
| 跨草稿资源引用失效 | P5/P6 | 会话校验，无法解析时降级；不假装跨应用可用 |
| 撤销和释放冲突 | P6 | 第一版保留到草稿结束，图片数/文件限制控制规模；后续再讨论历史驱动回收 |
| 运行测试却读到旧 dist | P0/每次回归 | 记录导入源，变更后刷新产物再验证 |
| 组合扩展导致整体 setContent | P7/P8 | 第一版限制组合并文档化，不连带重写其他扩展 |
