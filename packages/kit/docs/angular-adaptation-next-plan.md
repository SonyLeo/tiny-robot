## 3. 源码复核发现与决策建议

1. **保留现有消息连接设计。** native `getState()` 复制数组，消息和嵌套对象仍是引擎持有的可变对象。Angular `OnPush` 子组件读取或接收 revision；业务字段修改通过 `updateMessage`。只读 Signal 并不表示内部对象深度只读。继续保持对象身份，不逐 token 深拷贝全历史。
2. **会话规则共用，框架连接分别保留。** 核心负责会话列表、引擎所有权、加载去重、操作代际、保存调度与删除顺序；Vue 保留代理和 deep watch，把变化交给共享保存规则；Angular 用订阅和受控更新触发同一规则。核心不读取 Vue Ref 或 Angular Signal。
3. **按实际消费能力补缺口。** 新版消息文档允许初始化后的界面调整；当前 `updateMessage` 只能修改现存对象，不能单独替换、删除或清空消息列表。先查明业务与 Vue 实际用法，再设计最小受控列表操作及“活动回合禁止哪些修改”的规则；不能将 `send()` 当成只改历史的方法。只读分析尚不能断言必须新增哪组 API。
4. **尾保存是明确的行为改进。** 新版会话文档承认回收引擎前可能丢失节流末次更新；现有 stopAutoSave 只停止 watch，节流函数没有对外 flush/cancel。D3 建议在回收与释放时处理尾保存，保存/删除仍走同 ID 队列；兼容说明写明修复了这一限制。
5. **把视图卸载、取消、运行时释放、删除历史分开。** 页面连接共享会话时只解绑，管理器继续持有后台请求与暂停回合。单消息自有连接销毁仍会 abort；不能用它承诺导航保留审批。管理器最终释放的请求终止、最后保存、暂停快照保留/清理必须分别定义和验证。
6. **恢复必须同时有消息与回合元数据。** `turnPersistence.ts` 使用独立 localStorage 键 `__tiny-robot-turn`，按 turnId 保存多个快照，写入是 best effort；会话消息存储与快照没有事务。优先复用该格式，验证多会话匹配、暂停消息保存、失败、重载、删除后的残留；发现不能局部满足时回到设计评审，不预先发明第二套回合持久化。
7. **保留既有返回值与失败规则。** Vue `createConversation` 同步返回，`clear` 和改名返回 void；未知会话、初始加载失败、显式保存失败的行为以新版文档和测试为准。需要可等待清理时新增异步方法并保留包装；具体名称先审查。
8. **先补既定子入口。** 推荐 `/core` 明确导出框架无关会话、存储、SSE 与必要 Provider 能力，检查根入口和 core 的同名类型冲突。Angular 入口只负责消息/会话连接；Vue 根入口保持消费方式。`createVueMessageAdapter` 原 core 路径变化仍须核对发布产物、记录迁移。

用 Vue 作参照：`useConversation` 中 refs 与 deep watch 对应框架连接，而“同一会话的保存必须先于删除完成”是共享规则。Angular Signal 负责让组件看到变化，不能承担这些持久化与并发规则。

## 5. D3 可执行场景与预期

| 场景 | 预期/断言 |
| --- | --- |
| 初始列表晚到，期间创建/改名/删除/清空 | 内存新状态优先；空存储仍把内存列表交给 onLoad；晚到旧列表不能复活已删会话 |
| 快速选择 A→B，故意让 A 加载更晚 | 最后一次选择 B 保持活跃；并发加载同 ID 只创建一个引擎；加载失败遵守既有 fallback/错误规则 |
| 旧实例加载中，删除并以同 ID 重建 | 旧代际的加载、订阅和保存不覆盖新会话；删除完成后新数据仍在 |
| 多次流式更新后立即切换/回收 | 尾保存包含最后内容；停止监听后没有遗留 timer 写错目标；只在实际保存时按约定物化数据，不按 token 深拷贝全历史 |
| 阻塞一次保存，随后改名/删除/重建 | 同 ID 持久化有确定顺序；旧保存不能在删除之后复活历史；其他会话不被该队列阻塞 |
| 自定义 storage 收到参数后延迟读取，再修改消息 | 保存的数据版本遵守约定；不能因可变引用静默改写已排队版本。明确快照取值时机与序列化成本 |
| Vue 直接写消息内容/嵌套工具字段；Angular updateMessage | 两者按各自契约触发同一保存规则；消息对象身份、插件可见状态与 OnPush 呈现一致 |
| A 请求未结束时切换到 B，B 也发送 | 两个引擎隔离；A 后台完成并保存；B 界面不会收到 A 的内容 |
| 工具/Skill 待审批，导航离开再返回、整页重载 | 使用已存消息及回合快照恢复；资源 resolver 重建成功再执行；缺快照或缺资源时给出既有确定结果，不重复执行已完成工具 |
| 删除待审批或生成中的会话 | 取消该会话、清理相应快照与存储；其他会话的审批和快照不受影响 |
| view dispose、manager dispose、重复 dispose | 解绑不等于 abort；manager 释放处理自有请求与保存；幂等，历史不会因 dispose 被删除；已销毁连接不再发布 |
| 存储保存/删除失败、不合作的 Provider、销毁后迟到 | 错误有可等待或明确报告路径；队列不会因单次失败永久阻塞；旧结果不再改变已销毁状态。永不返回 Provider 的等待限制不得写成已修复 |

暂停持久化是多步骤且本地快照 best effort，不承诺浏览器强制退出时异步写入全部完成。验收应同时包含成功写入后的重载和写入失败的确定结果。

## 8. 已确认的架构与待评审契约

### 已确认，实施时保持

- 共享核心处理业务规则；Vue 和 Angular 适配各自连接框架状态和生命周期。消息引擎只保留一份。
- Vue 根入口和文档化业务能力保持兼容。Vue ref/computed、插件上下文及直接改消息后的深度自动保存继续有效。
- Angular 应用中的服务持有共享会话管理器。组件持有连接，卸载只解绑；后台请求、消息和待审批状态由管理器持有，组件重新连接后可继续操作。
- 单消息自有连接的 dispose 与共享会话视图解绑是不同操作；取消、管理器释放与删除历史分别定义。
- Angular 首版按业务消费能力对等，不复制 Vue 内部符号；Skill 复用核心选择 getter。SSR 暂无要求，responseProvider 继续是传输边界。

### 先写成可执行契约，再实现

| 事项 | 本计划的推荐规则 | 评审依据 |
| --- | --- | --- |
| 管理器最终释放 | 停止接收新操作，停止状态发布，处理自有活动请求并刷出最终保存；保留历史。重复释放返回同一结果 | D3a 用例明确保存失败如何报告、释放等待什么；永不结束的 Provider 限制如实保留 |
